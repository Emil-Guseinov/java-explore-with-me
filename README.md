# ExploreWithMe — сервис статистики

Первый этап диплома, ветка `stat_svc`.

## Модули

- `stats-dto` — общие объекты запросов и ответов.
- `stats-client` — HTTP-клиент для подключения из основного сервиса.
- `stats-server` — приложение на порту 9090 с отдельной PostgreSQL.
- `ewm-service` — пустой модуль основного сервиса: минимальный POM и Dockerfile.
  Реализация будет добавлена на втором этапе.

В POM пустого основного модуля оставлены только обязательный `modelVersion`,
родитель и `artifactId`, как требует инструкция первого этапа. Actuator уже
подключён к запускаемому `stats-server`; в `ewm-service` он появится вместе с
приложением на втором этапе.

`POST /hit` сохраняет обращение. `GET /stats` возвращает статистику по диапазону
времени, списку URI и флагу `unique`. Результаты группируются по app/URI и сортируются
по числу обращений. При `unique=true` считается число различных IP в каждой группе.
Границы диапазона включаются. Формат даты: `yyyy-MM-dd HH:mm:ss`.

## Запуск

Нужны JDK 21, Maven 3.9 и Docker Compose. В Windows откройте Docker Desktop.
Из каталога с этим README:

```shell
mvn clean install -P check
docker compose up --build -d
```

Проверка готовности: <http://localhost:9090/actuator/health>.
База PostgreSQL доступна на порту 5433, имя базы и логин `stats`, пароль `stats`.
Эти параметры предназначены для локального запуска.

```shell
docker compose logs stats-server
docker compose down
```

Данные остаются в Docker volume при обычной остановке.

Обычный `docker compose up --build -d` запускает только статистику и её БД.
Заготовки `ewm-service` и `ewm-db` объявлены в профиле `main`, который на первом
этапе включать не нужно: основной сервис пока не является исполняемым приложением.

## Дополнительная функциональность

Выбрана тема «Комментарии»: пользователь сможет оставлять комментарии к
опубликованным событиям, редактировать и удалять свои комментарии. Администратор
сможет удалять комментарии при модерации. Публичное чтение — постраничное.
Реализация начнётся после принятия основной части, в ветке `feature_comments`.

## Проверки

```shell
mvn test
```

26 JUnit-проверок охватывают агрегирование, уникальные IP, границы диапазона,
ошибки запросов, URL-кодирование и обработку HTTP-ошибок клиентом.
Тестовая БД — H2 в режиме PostgreSQL. H2 не входит в runtime-зависимости сервера.
Профиль `check` включает Checkstyle и SpotBugs с правилами официального шаблона.

При подготовке проекта выполнены все 26 тестов и официальная Postman-коллекция
первого этапа: 12 assertions, 16 HTTP-запросов, без ошибок. HTTP-проверка выполнялась
на настоящем Spring Boot приложении с внешней H2. Docker/PostgreSQL в проверочном
окружении были недоступны; запуск контейнеров нужно подтвердить локально.

## Сдача первого этапа

Используйте личный репозиторий, выданный Практикумом. В нём создайте ветку
`stat_svc` от `main`, перенесите содержимое этого каталога, сохранив `.git`, и
откройте Pull Request в `main`.

Репозиторий должен быть публичным. На первый этап предусмотрены две итерации
ревью, поэтому перед отправкой нужно подтвердить запуск контейнеров с PostgreSQL
и дождаться успешных GitHub Actions. После принятия PR объединяется с `main`.

Исходные `.github/workflows/api-tests.yml` и `checkstyle.xml` из репозитория курса
менять не нужно. Не добавляйте в Git `target`, архивы, JAR и настройки IDE.

После принятия и слияния первого этапа создайте ветку `main_svc` от обновлённой
`main` и используйте отдельный архив с основной частью.
